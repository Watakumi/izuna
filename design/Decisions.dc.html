Izuna / 設計の決定 2026-09-07
画面そのものはここに描かない。実装が正である。 手書きの複製を保守すると必ずずれる —— 実際に「実装に合わせてモックから消し、 あとでモックに合わせて実装に足し直す」を同じ箇所でやった。 ここに残すのはなぜそうなっているかだけ。実物は pnpm dev で見る。
見た目
アンバーは「人間の判断を待っている箇所」だけ
並列で最も壊れるのは承認の取りこぼし。実行中にも完了にも同じ色を使うと、探すべきものが埋もれる。装飾には一切使わない。
金額を出さない
costBasis: "list" の定価換算であって請求額ではない。出すと課金されているように読める。代わりに枠の使用率を出す —— こちらが実際の制約で、ターミナルの Claude Code と同じ窓を共有する。
破壊的な操作を同じ形にしない
「中断」は実行中の破壊的操作、「準備」は環境設定。同じ ghost ボタンで等間隔に並べると押していいものと危ないものの区別がつかない。中断だけ赤で分け、実行中のみ出す。
インスペクタは「目をやる頻度」順
WORKTREE → FORGEJO → 枠 の順。どこで作業しているか → 次に何を出すか → あとどれだけ走らせられるか。並べただけでは順序にならない。
同じ情報を 2 箇所に置かない
実行役をインスペクタにも出していたが、会話の下の TaskPanel と二重でしかも劣化版だった。狭いほうを見る理由が無い。
構造
行き来する画面をモーダルにしない
PR とブランチは会話と往復しながら使う。モーダルにすると戻る導線が「閉じる」だけになる。右ペインのタブにして並べて見られるようにした。
ターミナルはインスペクタに入れない
幅 288px では端末として狭すぎる。会話の下に敷く。VT の解釈と描画は ghostty-web（libghostty-vt の公式 WASM）で、main は PTY を持つだけ。端末なので ANSI を落とさない —— 落とすのは会話ビュー側の話。
承認は会話に埋めず別置き
差分は常時開いて出し、承認バーはその下に置く。モックは「差分を見て許可」を押させる作りだったが、見る前に押させる形は承認になっていない。
サイドバーはリポジトリで束ねる
並列で走らせるとどのリポジトリの話か分からなくなる。worktree は ~/.izuna/worktrees/<repo>/<branch> なのでそこから推測できる。
言葉
Sandbox / Upstream
「作業場 / 出口」は比喩が二重だった —— 出口は方向の比喩なのに GitHub は通過点ではなく本拠地。git の標準語彙に寄せ、型名まで揃えた（UI だけ変えると古い比喩がコードに残る）。
実行役 = サブエージェント
別セッションではなく Agent ツールのサブエージェント。承認は agentId 付きで人間に届く（実測）。worktree は Claude Code の agent isolation が配るので、Izuna が自前で配らない。
このキャンバスの使い方 まだ作っていない画面だけを描く。作ったら外す。 実装済みの画面をここに残すと、絵と実物のどちらが正か分からなくなり、必ずずれる。 決めたことは上の表と CLAUDE.md に残す。
