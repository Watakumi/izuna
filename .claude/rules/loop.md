# 自律ループと起床

文脈を毎回捨てて回す。進捗は申告させる。起床は覚えのある id だけ起こす。

## 23. 自律ループ（2026-09-08）

Nimbalyst を 5 領域に分けて読み、**入れると決めた 4 つ**を入れた。

### 進捗は「宣言させる」。文面から推測しない

`izuna_progress` という MCP ツールを与え、反復の終わりに申告させる。
**SDK の `createSdkMcpServer` でプロセス内に建てられる**ので、別プロセスは
要らない（Nimbalyst は同じことに 752 行使っていた。こちらは約 30 行）。

§7 で「**拒否は結果の文面から判定してはいけない**」を痛い目で学んだが、
同じ規律が進捗にも当たることに気づいていなかった。

### 引き継ぎは**プロンプト本文に入れる**

**文脈は毎回捨てる。** 反復ごとに新しいターンを起こし、引き継ぐのは
`progress.json` の `learnings` だけ。それを**次の本文に書き込む**。

Nimbalyst はここで矛盾していた —— プロンプトが「冒頭のスナップショットを
見よ」と言うのに、スナップショットは UI 用に DB へ書かれるだけで
**モデルには届かない**（毎回新セッションで履歴を渡していない）。
真似しなかった。

### 承認は迂回しない

**これが一番の判断。** 追いかけた結果、Nimbalyst も自律ループのために
権限を特別扱いしていなかった。

```
SuperLoop → セッション作成（mode を渡さない）→ 既定 'agent' → 'default'（毎回聞く）
```

自律で回るかどうかは、**人がプロジェクトを開いた最初に一度だけ選ぶ信頼モード**
だけで決まる。セッションの種別（対話・ループ・cron・teammate）は権限に
一切影響しない。**軸は 1 本**である。

Izuna も同じにした。`ModeSwitch` が既に人に選ばせているので、
`docs/GOAL.md` の完成の定義 5（承認は人間が持つ）を崩さずに済む。

**入れなかったもの**: Nimbalyst のメタエージェントは、子セッションの承認を
**プロンプトの指示でモデルに押させて**いる（`prompt.ts:369-370`）。しかも
`respondedBy: 'desktop'` として記録されるので、**監査の記録が嘘になる**。

### 承認に上限を付けた

§6 に「答えないまま放置すると CLI は待ち続ける」と書きながら、
**上限を置いていなかった**。人が見ているうちは露呈しないが、
**無人で回した瞬間に固まる**。5 分で deny する。

**「人が拒否した」と「誰も答えなかった」を文面で区別する。**
前者はやり方を変えるべきで、後者は人を呼ぶべきなので、次の一手が違う。

### 起床の予約

`~/.izuna/wakeups.json`。**DB は使わない**（§18 と同じ理由。数は高々数十件）。

**閉じているあいだに過ぎたものは、自動で発火させない。** `overdue` にして
見せ、人に決めさせる。夜中の予約が翌朝一斉に走り出す事故を避ける。
タイマーは**1 本だけ**張る（件数分撒くと、消したはずのものが二重に起きる）。

**張る前に期限が来ていても起こす**（2026-09-09 に GitHub の runner で踏んだ）。`add()` は保存してから
タイマーを張る。保存が遅いと張る時点で期限が過ぎ、`next()` が null を返してタイマーを張らず、
誰も起こさなくなっていた。`#arm` は `due()` に残りがあれば次が無くても tick する。
検査の固定待ち（900ms）も同じ日に全部「起きるまで待つ」に変えた。

### コミット文の下書き

**差分の中身は渡さない。** 変更の意図は会話に出ていて、diff からは読み取れない。
触ったファイルと直近のコミット件名だけを材料にする。
返りの ``` 囲みと前置きは外す。

### 止まらないことと、止まりすぎることの両方を検査した

- 進捗を申告せずに終わる反復があっても、**同じ本文で回り続けない**
- 続けて 3 回失敗したら**人を呼ぶ**（同じ場所で回り続けない）
- 最後の反復で終わったら「完了」。「上限で打ち切り」にしない

### Nimbalyst の SuperLoop は、たぶん動いていない

読んだ限り、`initSuperLoopListeners()` の**呼び出し箇所がゼロ**で、
MCP の進捗サーバも**明示的に無効化**されている
（`main/index.ts:196`「server disabled - leaking into non-super-loop sessions」）。

**「あちらにあるから安心」ではない。** 設計は参考になるが、動作の裏付けは無い。
