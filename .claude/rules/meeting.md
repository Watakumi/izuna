# 会議

役を決めたエージェントを集めて議題を話させ、発言録と議事録を残す。手は動かさない。

## 39. 会議（2026-10-06）

利用者の依頼（原文）:「izuna内でエージェントを組み合わしてミーティングや相談ができるような仕組みが欲しい。
コンテキストも保持して議事録のように」。用途は 3 つと答えた —— 実装前の設計相談、プロダクトの判断、壁打ち。
進行は司会エージェント、文脈は**会議を跨いで覚える**、参加者は**定型の役から選ぶ＋自作**。

**画面が答える問い**: 「あの件、誰が何と言って、何が決まったか」と「いま話しているのは誰で、どこまで進んだか」。

### ブレインと実行役（§12）とは別物

| | ブレインと実行役（§12） | 会議（§39） |
| --- | --- | --- |
| 何をするか | 作業を分けて手を動かす | 話して決める。**手は動かさない** |
| 参加者 | サブエージェント（使い捨て） | 独立した `query()` セッション。(リポジトリ, 役) ごとに 1 本を resume し続ける |
| 道具 | 全部（承認は人へ） | Read / Glob / Grep だけ。承認が来たら断る |
| 共有 | `~/.izuna/teams/<team>/` | `~/.izuna/meetings/<会議>/` |

### 置き場と書き手

```
~/.izuna/roles/<name>.md                 役。frontmatter の title と、立場の本文。利用者が直す・足す
~/.izuna/meetings/members.json           { <cwd>: { <役>: <claude の session id> } }。会議を跨いだ覚え
~/.izuna/meetings/<YYYYMMDD-HHmmss>/
  meeting.json    控え。議題・cwd・役・司会の session id・state（open / closed）・seen（誰にどこまで渡したか）
  transcript.md   発言録。`## <ISO8601> · <話者>` の見出しで追記のみ
  minutes.md      議事録。閉じるたびに「決まったこと / 残った問い / 宿題」を追記のみ
```

**書き手は Izuna だけ**（§12 の「1 ファイル 1 書き手」と同じ理由）。司会は `izuna_close` で中身を**申告**し、
Izuna が書く。文面から議事録を推測しない（§23 の `izuna_progress` と同じ規律）。
役の置き場が**無いときだけ**同梱の 6 役（`shared/meeting.ts` の `DEFAULT_ROLES`）を書き出す。
置き場があれば触らない —— 利用者が消した役を黙って戻さない。

### 実測（2026-10-06、`scripts/probe-meeting.ts`）

一時ディレクトリで司会 1・参加者 2（設計・セキュリティ）、議題「メモの複数端末同期」。

**1 回目は失敗した。** `izuna_next` の手がすぐ返る作りにしたら、司会は 1 ターンで指名を 6 回続けて
`izuna_close` まで呼び、**発言を一度も読まずに閉会した**（閉会の文に「発言内容が返ってこなかった」と自分で書いた）。

**2 回目。** 手は**参加者が話し終わるまで返らず、発言をツールの結果として返す**ようにした。

| 問い | 結果 |
| --- | --- |
| 司会は毎回ツールで指名するか | する。会議全体が司会の 1 ターン（47 秒）に収まり、3 発言で自分から `izuna_close` した |
| 差分だけ渡して噛み合うか | 噛み合う。セキュリティが設計の案に名指しで応じ、設計もそれを受けて保存形式を足した |
| 1 発言の時間 | 3〜6 秒 |
| 費用（定価換算。Pro の OAuth なので請求ではなく枠を食う。§14） | セッションの初回が 1.65 ドル前後（system prompt のキャッシュ書き込み）、以降は 1 発言 0.05 ドル前後。会議 1 回で 3.79 ドル |
| 参加者を resume すると前の会議を覚えているか | **覚えている。** 自分と設計の前回の主張を正しく言えた |
| 承認 | 参加者からは 0 件。司会の会議ツールは毎回来た → `allowedTools` で通す（下） |

**出どころ（`origin`）も測った。** 参加者に渡す文は人の発言と他の参加者の発言の中継なので、`human` と
名乗らせると出どころを偽る（§26）。`peer`（`from: 'izuna-meeting'`）も `channel` も保留されずに届いた
（6.5 秒 / 7.8 秒。同じ権限モードのクラスなので `crossSessionInbound` の保留は起きない。§12）。
受け手は「architect と名札の付いた発言として受け取ったが、本人のものかは確かめられない」と答えた。`peer` を使う。

### 決めたこと

- **会議は司会の 1 ターン。** 指名の手が発言を返すので、司会の文脈に全発言が自然に積まれる。
  会議の途中で司会に新しい user メッセージを送らない
- **参加者には差分だけを渡す。** この会議の中で前に渡した位置（`seen`）から後だけ。本人は resume で覚えている
- **人の割り込み**は発言録に足し、次の `izuna_next` の結果の頭に `【あなた（人）】…` として混ぜる。
  「締める」は止めずに、次の指名の代わりに「閉じよ」と返す。発言は 1 回 8 件まで（`MAX_TURNS`）
- **続きを話す**は司会を resume して人の一言を送る。閉じた会議も開き直し、議事録は下に足す
- **resume が効かなければ**（記録が消えた等）、覚えを捨てて 1 度だけ新しく起こす
- 司会の道具は `tools: []`、会議の 2 つの口だけを `allowedTools` に入れる。**Izuna 自身の MCP の口で、
  外に効果が出ない**ので人に聞かない。規則 1（承認は人が持つ）は外に効く操作の話で、ここに当たらない。
  それ以外の承認は**断る**（fail-closed）—— 道具を読むだけに絞ってあるので、来るのは外を読もうとしたとき
- 参加者は**リポジトリの中で読む**ので、開く前に `gateProjectHooks`（§26）を通す。鍵の覆い（§36）も掛ける
- 次の会議の司会には、同じリポジトリの閉じた会議の議事録を新しい順に 3 件添える（`PAST_MINUTES`）
- 通知は閉じたときと壊れたときだけ。発言のたびに鳴らさない（`shared/notice.ts`）
- 画面は覆い。入口はサイドバーの「会議」。人の発言の色にアンバーを使わない（承認待ちだけの色。Sidebar の註）

### 3 回目のレビューで、印を足すのをやめた（2026-10-07）

3 回目も 10 件。うち 3 件（止めたあとに偽の「答えられませんでした」を書く、終了時に起こしている途中の会議が残る、
止めた直後に話すと 2 つの回が重なる）は、**直すたびに「止められたか」の印を足してきた形そのもの**から来ていた
（`stopped`・`#starting`・`#cancelled`・`halt()`…）。待つ場所が増えるたびに確かめ忘れが出る。

**形を変えた。**

- 回（`Run`）は**起こした瞬間に載せ、片付けが終わるまで外さない**。1 つの会議に回は 1 つ。止めたらセッションを止めて
  「止められた」にするだけで外さない。止めた直後に人が話した分は `again` に記し、片付けが終わってから次の回で渡す
- **止められた回は何も書かない。** 発言録（司会と参加者の分）・控え・議事録の書き込みは、すべて入口で見る
- `#starting` と `#cancelled` は要らなくなった。終了時の停止は、起こしている途中の回にも届く

ほかに直したもの:

| 指摘 | 直し方 |
| --- | --- |
| 司会への続きの文に参加者の発言が混ざるのに `human` で送る | 人の発言だけなら `human`、混ざれば `peer`（`originOf`） |
| 壊れたことが 2 度通知される | セッションの `error` は記録だけにし、待っているターンの側から 1 回だけ言う |
| 一時ファイルの検査が、もう無い名前を見ている。失敗した一時ファイルが溜まる | どの名前でも残っていないことを見る。失敗したら消して投げ直す（`test/main-fsx.test.ts`） |
| 画面の読み直しの途中に来た出来事をまた落とす | 読み直さず、読み込みの途中に来た出来事を溜めて、読み終わった中身に重ねる。同じ発言は 2 度足さない |
| リポジトリの許可の規則で、承認を経ずに外を読めうる | 参加者に **PreToolUse の hook** を付け、道具が動く前に読む場所を見る（`outsideScope`）。下の実測 |
| 控えを 1 件ずつ読む | 並べて読む |

**測ったこと（2026-10-07）。** リポジトリの `.claude/settings.json` に `permissions.allow: ["Read"]` を置き、`/etc/hosts` を読ませた。

| 条件 | 結果 |
| --- | --- |
| hook 無し | 承認が来た（作業ディレクトリの外なので、`Read` の許可では通らなかった）。断れた |
| hook あり | **承認の前に hook が断った**（`Read:/etc/hosts:deny`） |

この規則の書き方では穴にならなかったが、`Read(//**)` のような絶対パスの規則は試していない。hook なら規則の書き方によらず
同じ判定で止まるので付けた。**記号リンクの先は見ていない**（`readableUnder` は字面で判定する。§34 の読む口は実体で見る）。

### 覆る条件

- 司会が `izuna_next` を呼ばずにターンを終える形が頻発したら、ターンの終わりで「続けるか閉じるか」を
  促す 1 通を送る形を足す（2 回目の測定では 0 回だった）
- 費用が問題になったら、参加者を軽いモデルにする選択を足す（`SessionOptions.model`）。いまは既定のまま
- (リポジトリ, 役) の覚えが長くなりすぎて的外れになったら、`members.json` から消せば次は新しく起こす。
  消す口は画面にまだ無い
