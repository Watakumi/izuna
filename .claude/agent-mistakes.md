# エージェントの失敗の記録

作業を始める前に読む。**同じ形の失敗を二度しないため**の記録で、反省文ではない。
形は「日付、何が起きたか、利用者の言葉（あれば）、根本原因、教訓」。
Nimbalyst の `.claude/agent-mistakes.md` から取った（docs/NIMBALYST.md §3）。

新しく足すときは上に。古いものは消さない。

## 2026-09-09: ハーネスの都合を本物の不具合と誤診し、人に作業を頼んだ

**何が起きたか**: `pnpm e2e` を Playwright の `_electron.launch` で書いた。Forgejo の段が
「トークンが読めない」で skip され、アプリの中で復号を試すと失敗した。keychain に
`izuna Safe Storage` が 2 項目あるのを見つけ、「鍵が変わった、発行し直してほしい」と報告した。
利用者は発行し直したが、直らなかった。

**利用者の言葉**: 「トークンは発行しているが、なぜ何度も発行しないといけない？」

**根本原因**: Playwright の Electron 起動は `--use-mock-keychain` を付ける
（`playwright-core/lib/server/electron/loader.js`）。ハーネスの中だけ鍵が違った。
素の `electron .` を起動して同じことを聞けば一発で分かったのに、ハーネスの結果を本物と信じ、
keychain の 2 項目という**それらしい別の事実**に原因を当てはめた。

**教訓**: ハーネスが「本物が壊れている」と言ったら、**ハーネス無しで再現してから**人に言う。
それらしい事実が見つかっても、それが原因だと示す実験（その事実を外すと直るか）をしてから書く。
人に作業を頼む報告は、推測と確認済みを分けて書く。

## 2026-09-08: 道具の hook に止められた命令を、そのまま出し直しかけた

**何が起きたか**: 5 つのファイルを 1 つの Bash で書こうとして、コマンド文中の語の
組み合わせ（コミットの命令と検査回避の語）をプラグインの hook が誤検知して止めた。

**教訓**: ファイルの中身を Bash のコマンド文に載せない。Write で置いて、実行だけ Bash にする。
hook に止められたら、同じ文をそのまま出し直さない。

## 2026-09-08: 置換の範囲が広すぎて、ファイルの大半を消した

**何が起きたか**: `shared/ipc.ts` の `IPC_VERSION` の塊だけを差し替えるつもりで、
非貪欲の正規表現 `/\*\*\n \* ([^\n]*\n)*? \*/` で JSDoc を探した。先頭の JSDoc から
目的の行まで一致し、型定義ごと置き換えた。型検査が落ちて気づいた。

**根本原因**: 「一致した範囲を見ずに置換した」。正規表現は最初に見つかった `/**` から
最初に満たせる終端まで伸びる。目的の塊だけに一致する保証は無かった。

**教訓**: 置換の前に、一致した文字列を印字して見る。JSDoc のような繰り返す形は、
正規表現ではなく**その塊にしか無い文字列**（`export const IPC_VERSION = 19`）で切る。
壊したら `git checkout -- file` で戻してからやり直す。継ぎ足しで直さない。

## 2026-09-08: 保存された出力の先頭だけ読んで「無い」と言った

**何が起きたか**: セキュリティ分析で `dangerouslySetInnerHTML` を grep した。
結果は大きくてファイルに保存され、先頭 2KB の抜粋だけが見えた。抜粋に無かったので
「ゼロ」と報告した。`Mermaid.tsx` に 1 か所あった。あとのレビューで自分で見つけた。

**根本原因**: 「抜粋を全体だと思った」。保存先のパスは書いてあったのに読まなかった。

**教訓**: 出力が保存されたと言われたら、結論を出す前にその**ファイルを読む**。
「無い」は「全部見て無かった」ときにしか言えない。見た範囲を言葉にする
（「先頭 2KB に無い」は「無い」ではない）。

## 2026-09-08: 見出しの正規表現が「10.」を拾えなかった

**何が起きたか**: CLAUDE.md を節ごとに切るとき `^## \d+(\.\d+)? ` で見出しを探した。
`## 17.4 …` は拾えたが `## 10. …` は句点があって拾えず、`KeyError` で落ちた。

**根本原因**: 見出しの形を 2 つ（`N.` と `N.M`）とも確かめずに書いた。
先に `awk` で見出しを数えたとき、その出力に句点が見えていたのに使わなかった。

**教訓**: 形を切る正規表現は、**対象の全部に当ててから**使う。
`grep -c` で一致数と実際の数が合うことを見る。1 件でも違えば形が違う。

## 2026-09-08: renderer の検査で前の描画を片付けなかった

**何が起きたか**: `@testing-library/react` の `render` を検査ごとに呼び、
`cleanup` を入れなかった。vitest は自動で片付けないので、前の検査の要素が残り、
`getByText` が「複数ある」と 3 件落ちた。

**根本原因**: Jest の既定（自動 cleanup）を vitest にも期待した。

**教訓**: vitest で RTL を使うなら、各ファイルに `afterEach(cleanup)`。
「複数ある」で落ちたら、まず自分の検査が片付けていないことを疑う。

## 2026-09-08: 検査の足場を、別のスコープの名前で書いた

**何が起きたか**: 既存の検査ファイルに追記するとき、その `describe` の中で使える名前
（`input`、`ClaudeSession`）を確かめずに書き、2 件が未定義で落ちた。
`import` の行も、別ファイルの vitest の import に `split` を混ぜて壊した。

**根本原因**: 追記先の**周りを読まずに**貼った。

**教訓**: 既存ファイルに足すときは、足す場所の前後 20 行と import を先に読む。
機械的な置換で import を触らない。
