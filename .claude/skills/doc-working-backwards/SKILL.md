# Working Backwards（PR / FAQ）

出来上がったときのプレスリリースと FAQ を**先に**書く。**この資料の値打ちは、書けなかったところが
「未定」として出てくること**にある。埋まった文章ではなく、埋まらなかった穴を見るために書く。

## いつ使い、いつ使わないか

使う:

- 次に何を出すかを人と決めたい
- 作ろうとしているものが、誰の何を変えるのか言葉にできない
- 決める前に、決まっていないことを全部並べたい

使わない:

- **何を出すかの候補も無いとき。** `doc-impact-map` か `doc-now-next-later` を先に
- 既に作り始めていて、範囲だけ固めたいとき → `doc-example-map`
- 事実として公表する文章が要るとき（**これは下書きであって、公表する文章ではない**）

## 手順の形式

順序つきの手順。**1 → 4 を飛ばさない。** 題材が決まらなければ 2 で止まる。

## 手順

### 1. 入力を集める

- `docs/GOAL.md`（無ければ `README.md`）、`docs/DECISIONS.md`（あれば）
- `gh issue list --state open --limit 100 --json number,title`
- `gh pr list --state merged --limit 20 --json number,title`
- 題材。引数にあればそれ。無ければ GOAL の次の段を題材にし、**資料にそう書く**

### 2. 入力が足りるかを見る（**止まる判断**）

| 見るもの | 足りない | どうするか |
| --- | --- | --- |
| 題材 | 引数にも GOAL にも無い | 人に「何を出す前提で書きますか」と聞く。**自分で決めない** |
| 困りごとの根拠 | Issue も PR も 0 件 | 人に聞く。根拠の無い困りごとを書かない |
| GOAL | 文書に無い | 「やらないこと」が引けないので、FAQ の「何を作らないか」は空にして未定に落とす |

### 3. 書く

**事実でないことを事実の形で書かない。** 未定のものは FAQ の「未定」に置く。

- **見出し**: 1 行。誰が何をできるようになるか
- **困りごと**: いま何が困っているか。**Issue の番号を根拠に添える**。根拠が無ければ書かない
- **解決**: それがどう変わるか
- **利用者の言葉**: 想定利用者が言いそうな 1 文。**作り話であることを必ず明記する**
- **始め方**: 最初の 1 手。実行できる形で（コマンドか、押す釦の名前）
- **FAQ（中から）**: 何を作らないか（GOAL の「やらないこと」）、費用。**分からなければ「未定」**

### 4. 置く

`doc-shared/versioning.md` のとおり版を足す。置き場は `docs/plans/working-backwards/`。

```markdown
# <出すもの>（YYYY-MM-DD の下書き）

前の版（YYYY-MM-DD）からの変更: ...

## プレスリリース
**見出し**: ...
**困りごと**: ...（根拠: #12、#7）
**解決**: ...
**利用者の言葉**: 「...」（**作り話。実在の利用者の発言ではない**）
**始め方**: ...

## FAQ
### 利用者から
- Q: ... A: ...
### 中から
- Q: 何を作らないか A: （GOAL の「やらないこと」の X）
- Q: 費用は A: ...（分からなければ「未定」）

## 未定
- ...（決める人と、決めるのに要る材料）
```

## 適用範囲

- **出どころ**: Working Backwards は Amazon の PR / FAQ の形。作る前に press release と FAQ を書く
- **対象**: これから作るものの候補が 1 つ以上ある PJ
- **当てはまらなくなる条件**:
  - 公表する文章そのものを書きたいとき（**この資料は下書きで、事実ではない**）
  - 利用者が実在して聞ける場合（作り話の「利用者の言葉」より、聞いた言葉を使う）
  - 候補が無いとき（題材が決まらない。先に他の資料を作る）
- **確かめた環境**: Izuna のリポジトリ、2026-09-11

## 実行後に確かめる

```bash
ls docs/plans/working-backwards/
```

- 「困りごと」の各行に、**Issue か PR の番号**が付いている（根拠の無い行が 0）
- 「利用者の言葉」に**作り話だと明記**されている
- 「始め方」が実行できる形（コマンドか、画面にある釦の名前）で書かれている
- 「未定」の各行に**決める人**が書かれている
- 「何を作らないか」が GOAL の「やらないこと」と食い違っていない

## 受け取る側が得るもの

- `docs/plans/working-backwards/YYYY-MM-DD.md`（版）と `README.md`（索引）
- 決まっていないことの一覧（「未定」）。**これが本体である**
- 報告は**パスと「未定」の件数だけ**を 1 行で

## 読む順序

| 何を知りたいか | 読む |
| --- | --- |
| 入力の集め方 | `doc-shared/inputs.md` |
| 版の付け方 | `doc-shared/versioning.md` |
| 書いてはいけないこと（作り話の扱いを含む） | `doc-shared/writing.md` |
| なぜこう書いてあるか | `doc-shared/judgement.md` |
