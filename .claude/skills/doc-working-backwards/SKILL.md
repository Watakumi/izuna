# Working Backwards（PR / FAQ）

出来上がったときのプレスリリースと FAQ を**先に**書く。書けないところが、決まっていないところである。
PJ の今後を PdM と決める資料に使う。

## 読む

1. `docs/GOAL.md`（無ければ README）、`docs/DECISIONS.md`（あれば）
2. open な Issue と直近の PR（`gh issue list`、`gh pr list --state merged --limit 20`。通らなければ人に貼ってもらう）
3. 引数に「何を出すか」があればそれを題材にする。無ければ GOAL の次の段を題材にし、そう書く

## 書く

`docs/plans/working-backwards/YYYY-MM-DD.md` に書く（下の「版」）。**事実でないことを事実の形で書かない。** 未定のものは FAQ の「未定」に置く。

```markdown
# <出すもの>（YYYY-MM-DD の下書き）

前の版（YYYY-MM-DD）からの変更: ...

## プレスリリース
**見出し**: 1 行
**副題**: 誰が、何を、なぜ
**要約**: 3 文
**困りごと**: いま何が困っているか（根拠: Issue の番号）
**解決**: それがどう変わるか
**利用者の言葉**: 想定利用者が言いそうな 1 文（作り話であることを明記）
**始め方**: 最初の 1 手

## FAQ
### 利用者から
- Q: ... A: ...

### 中から
- Q: 何を作らないか A: （GOAL の「やらないこと」）
- Q: 費用は A: （分かる範囲。分からなければ「未定」）

## 未定
- （書けなかったこと。決める人と、決めるのに要る材料）
```


## 版

**上書きしない。** 資料ごとに置き場を分け、日付つきの版を足す（利用者の指示、2026-09-11。資料の版を個別に追えるように）。

- 置き場: `docs/plans/<資料名>/`。版は `YYYY-MM-DD.md`（同じ日に 2 回なら `YYYY-MM-DD-2.md`）
- 前の版があれば読み、新しい版の冒頭に「前の版（日付）からの変更」を 3 行以内で書く。無ければ「最初の版」
- `docs/plans/<資料名>/README.md` に版の索引を置く（新しい順。日付と 1 行の要約）。無ければ作る
- 資料ごとの歴史は `git log -- docs/plans/<資料名>/` で追える。PR にするなら資料ごとに枝を切る（`docs/<資料名>`）

## 報告

パスと、「未定」の件数を 1 行で言う。
