# Now / Next / Later

Issue を「いま」「次」「あと」の 3 列に振り、PdM と話す土台を作る。期日は切らない。
**読む → 並べる → 書く → 報告** の順で、途中で止まらない。

## 読む

1. `docs/GOAL.md`（無ければ README）で、何を作るか・やらないことを読む
2. open な Issue を集める。`gh issue list --state open --limit 100 --json number,title,labels,body` が通ればそれを使う。
   通らなければ、人に「Issue の一覧を貼ってください（番号と題名）」と頼み、貼られたものを使う
3. `git log --oneline -30` で、直近に何が入ったかを読む（Now の根拠になる）

## 並べる

- **Now**: 着手中か、次の 1〜2 週間で終わるもの。直近の commit が触っている領域
- **Next**: Now が終わったら着手するもの。Now に依存するものはここ
- **Later**: 価値はあるが順番が決まらないもの。GOAL の「やらないこと」に当たるものは **Later にも置かず「置かない」に列挙する**
- 根拠を 1 行ずつ添える（Issue の番号、commit、GOAL の節）。**根拠の無い順番を作らない** —— 分からなければ Later に置き、理由に「順番を決める材料が無い」と書く

## 書く

`docs/plans/now-next-later/YYYY-MM-DD.md` に書く（下の「版」）。

```markdown
# Now / Next / Later（YYYY-MM-DD）

前の版（YYYY-MM-DD）からの変更: ...

| Now | Next | Later |
| --- | --- | --- |
| #12 題名 — 根拠 | #7 題名 — 根拠 | #3 題名 — 根拠 |

## 置かない
- #5 題名 — GOAL の「やらないこと」の X に当たる

## 決めてほしいこと
- （順番が決まらなかった Issue と、決めるのに要る材料）
```


## 版

**上書きしない。** 資料ごとに置き場を分け、日付つきの版を足す（利用者の指示、2026-09-11。資料の版を個別に追えるように）。

- 置き場: `docs/plans/<資料名>/`。版は `YYYY-MM-DD.md`（同じ日に 2 回なら `YYYY-MM-DD-2.md`）
- 前の版があれば読み、新しい版の冒頭に「前の版（日付）からの変更」を 3 行以内で書く。無ければ「最初の版」
- `docs/plans/<資料名>/README.md` に版の索引を置く（新しい順。日付と 1 行の要約）。無ければ作る
- 資料ごとの歴史は `git log -- docs/plans/<資料名>/` で追える。PR にするなら資料ごとに枝を切る（`docs/<資料名>`）

## 報告

書いたファイルのパスと、「決めてほしいこと」の件数を 1 行で言う。資料の中身を会話に繰り返さない。
