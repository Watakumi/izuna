# 版の付け方

資料の skill 4 本（`doc-*`）が共有する。**上書きしない。** 資料ごとに置き場を分け、日付つきの版を足す
（利用者の指示、2026-09-11。資料の版を個別に追えるように）。

## 置き場

```
docs/plans/<資料名>/
  README.md        版の索引（新しい順。日付と 1 行の要約）
  YYYY-MM-DD.md    版。同じ日に 2 回なら YYYY-MM-DD-2.md
```

`<資料名>` は skill の名前から `doc-` を落としたもの（`doc-now-next-later` → `now-next-later`）。
Issue ごとに作る資料（`doc-example-map`）は `<番号>-YYYY-MM-DD.md`。

## 手順

1. `date +%F` で今日の日付を取る。**思い出しで書かない**
2. `ls docs/plans/<資料名>/` で前の版と、同じ日の版があるかを見る
3. 前の版があれば読み、新しい版の冒頭に「前の版（日付）からの変更」を 3 行以内で書く。無ければ「最初の版」
4. 書いたら `README.md` の表に 1 行足す（新しい順）。`README.md` が無ければ作る

## 確かめ方

```bash
ls docs/plans/<資料名>/                        # 版が 1 つ増えている。前の版は残っている
git log --oneline -- docs/plans/<資料名>/      # 資料ごとの歴史が追える
git check-ignore docs/plans/<資料名>/          # 何も出なければ版管理に入る
```

Izuna のリポジトリでは `docs/plans/` は gitignore されていない（2026-09-11 に確かめた）。
別のリポジトリでは確かめること —— ignore されていると、版が残らないまま資料だけが出る。

## PR にするなら

資料ごとに枝を切る（`docs/<資料名>`）。他の変更と混ぜない —— 資料は読む人が違う。
