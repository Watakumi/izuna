# Example Mapping

1 つの Issue（ストーリー）を、**規則**（受け入れ条件）・**具体例**（規則ごとの入力と結果）・**疑問**（決まっていないこと）に
分ける。具体例はそのまま検査になる —— このリポジトリの「変えたい挙動を検査で先に書く」に繋がる。

## 読む

1. 対象の Issue。引数に番号があればそれ、無ければ人に聞く。`gh issue view <番号> --json title,body,comments` が通ればそれを使い、
   通らなければ人に本文を貼ってもらう
2. 関係するコード。Issue の語で `grep` し、触るファイルを 3 つまで挙げる
3. 既存の検査（`test/`）で近いものを 1 つ読み、書き方を揃える

## 分ける

- 規則: 「〜なら〜」の形。3〜7 個。多ければ Issue が大きすぎる（分割を提案する）
- 具体例: 規則ごとに 1〜3 個。**入力と結果を具体的な値で書く**（「大きいファイル」ではなく「6MB のファイル」）
- 疑問: 規則にも具体例にもできなかったこと。**推測で埋めない。** 疑問のまま残し、誰が答えるかを書く

## 書く

`docs/plans/example-map/<番号>-YYYY-MM-DD.md` に書く（下の「版」。この資料は Issue ごとなので、名前に番号を含める）。

```markdown
# Example Map: #<番号> <題名>（YYYY-MM-DD）

前の版（YYYY-MM-DD）からの変更: ...

## 規則
1. ...

## 具体例
| 規則 | 入力 | 結果 | 検査の置き場（案） |
| --- | --- | --- | --- |
| 1 | ... | ... | test/xxx.test.ts |

## 疑問
- ...（答える人: PdM / 作者）
```


## 版

**上書きしない。** 資料ごとに置き場を分け、日付つきの版を足す（利用者の指示、2026-09-11。資料の版を個別に追えるように）。

- 置き場: `docs/plans/<資料名>/`。版は `<番号>-YYYY-MM-DD.md`（同じ日に 2 回なら `<番号>-YYYY-MM-DD-2.md`）
- 前の版があれば読み、新しい版の冒頭に「前の版（日付）からの変更」を 3 行以内で書く。無ければ「最初の版」
- `docs/plans/<資料名>/README.md` に版の索引を置く（新しい順。日付と 1 行の要約）。無ければ作る
- 資料ごとの歴史は `git log -- docs/plans/<資料名>/` で追える。PR にするなら資料ごとに枝を切る（`docs/<資料名>`）

## 報告

パスと、規則・具体例・疑問の数を 1 行で言う。疑問が 0 でないなら、検査を書き始める前に人に答えを求める。
