# Example Mapping

1 つの Issue を、**規則**（受け入れ条件）・**具体例**（規則ごとの入力と結果）・**疑問**（決まっていないこと）に
分ける。具体例はそのまま検査になる —— このリポジトリの「変えたい挙動を検査で先に書く」に繋がる。
**この資料の値打ちは、疑問が名指しで出てくること**にある。疑問を推測で埋めたら、この資料は無意味になる。

## いつ使い、いつ使わないか

使う:

- 1 つの Issue に着手する前に、受け入れ条件を決めたい
- 認識が揃っているか、人と確かめたい
- Issue が大きすぎるかどうかを見たい

使わない:

- **対象の Issue が決まっていないとき。** 番号を聞いてから使う
- 複数の Issue をまとめて扱いたいとき → `doc-now-next-later` か `doc-impact-map`
- 受け入れ条件が既に書かれていて、疑問が無いとき（作っても新しいことが出ない）

## 手順の形式

順序つきの手順。**1 → 4 を飛ばさない。** Issue が読めなければ 2 で止まる。

## 手順

### 1. 入力を集める

- 対象の Issue。引数に番号があればそれ、無ければ**人に聞く**
- `gh issue view <番号> --json title,body,comments`
- 関係するコード。Issue の語で `grep` し、触るファイルを 3 つまで挙げる
- 既存の検査（`test/`）で近いものを 1 つ読み、書き方を揃える

### 2. 入力が足りるかを見る（**止まる判断**）

| 見るもの | 足りない | どうするか |
| --- | --- | --- |
| Issue の番号 | 引数に無い | 人に聞く。**適当に選ばない** |
| `gh issue view` | 失敗した | 人に本文を貼ってもらう |
| 本文 | 題名だけで中身が無い | 人に「何をしたいか、3 行で」と聞く。**自分で補わない** |

### 3. 分ける

- **規則**: 「〜なら〜」の形。**目安は 3〜7 個**（Example Mapping の通説。ここでは測っていない）。
  8 個を超えたら Issue の分割を**提案する** —— 勝手に分けない
- **具体例**: 規則ごとに 1〜3 個。**入力と結果を具体的な値で書く**。
  「大きいファイル」ではなく「6MB のファイル」、「古い版」ではなく「2.1.266」
- **疑問**: 規則にも具体例にもできなかったこと。**推測で埋めない。**
  疑問のまま残し、**誰が答えるか**を書く

具体例が 1 つも書けない規則は、規則ではなく願望である。疑問に落とす。

### 4. 書く

`../doc-shared/versioning.md` のとおり版を足す。置き場は `docs/plans/example-map/`、
ファイル名は `<番号>-YYYY-MM-DD.md`（この資料は Issue ごとなので名前に番号を含める）。

```markdown
# Example Map: #<番号> <題名>（YYYY-MM-DD）

前の版（YYYY-MM-DD）からの変更: ...

## 規則
1. ...

## 具体例
| 規則 | 入力 | 結果 | 検査の置き場（案） |
| --- | --- | --- | --- |
| 1 | 6MB の png | 「大きすぎます（上限 5MB）」 | test/images.test.ts |

## 疑問
- ...（答える人: 作者 / PdM）
```

## 適用範囲

- **出どころ**: Example Mapping は Matt Wynne の形。規則・具体例・疑問（と、もとのストーリー）の 4 色のカード
- **対象**: Issue 1 件。検査を書くリポジトリで一番効く
- **当てはまらなくなる条件**:
  - 受け入れ条件が機械的に判定できない作業（文章の良し悪しなど）。具体例が書けない
  - Issue が「調べる」で終わるもの（結果が決まっていないので規則にならない）
  - 規則が 8 個を超える Issue（分割を提案する段で止まる。これは失敗ではない）
- **確かめた環境**: Izuna のリポジトリ、2026-09-11。規則の個数の目安は通説で、ここでは測っていない

## 実行後に確かめる

```bash
ls docs/plans/example-map/
```

- 規則に**番号**が振られていて、具体例の表の「規則」列が全部その番号を指している（孤児が 0）
- 具体例の「入力」と「結果」に、**具体的な値**が入っている（「適切な」「正しい」だけの行が 0）
- 疑問に**答える人**が書かれている
- 検査の置き場が、実在するディレクトリを指している（`ls` で確かめる）

**疑問が 0 件でないなら、検査を書き始める前に人に答えを求める。** これを飛ばすと、
推測で書いた検査が「通った」という誤った証拠になる。

## 受け取る側が得るもの

- `docs/plans/example-map/<番号>-YYYY-MM-DD.md`（版）と `README.md`（索引）
- そのまま検査に落とせる具体例の表
- 報告は**パスと、規則・具体例・疑問の数**を 1 行で
