# ロードマップと物語の対応

`doc-story-map` と `doc-now-next-later` が共有する。**利用者の指示、2026-09-14 ——
「ロードマップ、ユーザーストーリーマッピングと対応していることが大事」。**

## なぜ要るか

ロードマップは Issue を並べる。Issue は**実装の単位**で、利用者が得るものではない。
物語の地図は利用者が得るものを並べるが、**誰がいつ作るか**を言わない。
別々に作ると、次の 2 つが見えないまま進む。

| 見えなくなるもの | 何が起きるか |
| --- | --- |
| どの物語にも紐づかない Issue | 作っても、誰の何が良くなるのか誰も言えない |
| どの Issue にも運ばれていない物語 | 大事だと決めたのに、誰も作っていない |

**どちらも「無い」という形で現れる**ので、突き合わせないと気づけない。

## 対応のつけ方

物語に**番号**を振る。`S-01` から通しで、地図の中で一意。番号は**消さない・付け替えない** ——
付け替えると、前の版のロードマップが別のものを指す。

- ロードマップの各行は、**運ぶ物語の番号を 1 つ以上書く**（`#45 … → S-07`）
- 番号が無い行は `→ 物語なし` と書く。**空欄にしない** —— 空欄は「まだ書いていない」と区別できない
- 地図の各物語は、**運ぶ Issue の番号を書く**（`S-07 … #45`）。無ければ `Issue なし`

## 突き合わせ（**両方向を見る**）

資料を書き終えたら、次の 2 つを数える。**片方だけでは足りない。**

```
1. ロードマップの行のうち `→ 物語なし` の数
2. いまの切り口（作ると決めた範囲）の物語のうち `Issue なし` の数
```

| 出たもの | どう書くか |
| --- | --- |
| 物語なしの Issue | 「決めてほしいこと」に**そのまま並べる**。消したり、それらしい物語を後から作らない |
| Issue なしの物語 | 同じく並べる。「作ると決めたのに誰も作っていない」と書く |
| どちらも 0 | そう書く。**0 件であることも結果である** |

**後から辻褄を合わせない。** 紐づかないものが出たら、それがこの資料の一番の収穫である ——
並んだ順番より、**噛み合っていない場所が名指しで出てくること**に値打ちがある。

## 置き場

```
docs/plans/story-map/YYYY-MM-DD.md        物語の地図（番号の出どころ）
docs/plans/now-next-later/YYYY-MM-DD.md   ロードマップ（番号を参照する）
```

新しいロードマップを書くときは、**一番新しい地図を読んでから**書く。
地図が無ければロードマップに `→ 物語なし` しか書けないので、そのときは
「物語の地図がまだ無い」と冒頭に書く（作れとは言わない。作るかは人が決める）。
