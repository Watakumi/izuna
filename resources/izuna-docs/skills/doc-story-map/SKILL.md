# ユーザーストーリーマッピング

利用者が**やること**を時間順に並べ、その下に**物語**を積み、どこまで作るかを線で切る。
この資料の値打ちは、並んだ物語より **ロードマップと噛み合っていない場所が名指しで出てくること**にある
（`../doc-shared/trace.md`）。

## いつ使い、いつ使わないか

使う:

- 機能の一覧はあるが、**利用者が通しで何をするのか**が誰も書いていない
- どこまで作るか（切り口）を決めたい
- ロードマップの Issue が、誰の何を良くするのか読めなくなった

使わない:

- **目標が無いとき。** やることを並べる軸が無い。`docs/GOAL.md` が無ければ止まる
- 順番だけ決めたいとき → `doc-now-next-later`
- 1 つの Issue を掘り下げたいとき → `doc-example-map`
- なぜ作るかから問い直したいとき → `doc-impact-map`

## 手順の形式

順序つきの手順。**1 → 5 を飛ばさない。** 入力が集まらなければ 2 で止まる。

## 手順

### 1. 入力を集める

`../doc-shared/inputs.md` の表のとおりに集める。要るのは 4 つ。

- `docs/GOAL.md`（無ければ `README.md`）の目標・完成の定義・やらないこと
- `gh issue list --state open --limit 100 --json number,title,body`
- 既にあるもの（`README.md` の機能、画面の見出し、`docs/` の一覧）
- `docs/plans/story-map/` の前の版（あれば）と `date +%F`

### 2. 入力が足りるかを見る（**止まる判断**）

| 見るもの | 足りない | どうするか |
| --- | --- | --- |
| 目標 | GOAL も README も無い | 人に「この道具で人は何をしますか」と聞く。**自分で決めない** |
| 完成の定義 | 無い | 無いまま進んでよい。ただし切り口は引かず、「切る材料が無い」と書く |
| Issue | 0 件でも進む | 地図は Issue が無くても作れる。突き合わせの結果が「Issue なし」だらけになるだけ |

### 3. 背骨を作る

**利用者がやることを、時間順に左から右へ並べる。** これが背骨である。

- 1 つの活動は**動詞で書く**（「準備する」「任せる」「出す」）。名詞で書くと機能の一覧に戻る
- 実装の都合で分けない。**人の 1 日の順番**で分ける
- 活動が 10 を超えたら粗い。まとめる
- 完成の定義（GOAL）に手順があるなら、**それが背骨の下敷き**になる。作り話で足さない

### 4. 物語を積む

活動の下に、その活動の中で人がやりたいことを 1 行ずつ積む。**上ほど欠けると困るもの。**

| 書くこと | 形 |
| --- | --- |
| 番号 | `S-01` から通し。**消さない・付け替えない**（`../doc-shared/trace.md`） |
| 物語 | 「〜したい」。利用者の言葉で書く。ツールの名前を主語にしない |
| 状態 | 済み / 途中 / 無い。**出来ているふりをしない**（実物を見て決める） |
| 運ぶ Issue | 番号。無ければ `Issue なし` |

**切り口を引く。** 上から何本目までが「いま作ると決めた範囲」かを線で示す。
切る材料が無ければ引かない —— 引いたふりをしない。

### 5. 書いて、突き合わせる

`../doc-shared/versioning.md` のとおりに版を足す。置き場は `docs/plans/story-map/`。

```markdown
# ユーザーストーリーマッピング（YYYY-MM-DD）

前の版（YYYY-MM-DD）からの変更: ...    ← 最初なら「最初の版」

## 背骨

1. 準備する → 2. 決める → 3. 任せる → …

## <活動の名前>

| 番号 | 物語 | 状態 | 運ぶ Issue |
| --- | --- | --- | --- |
| S-01 | 〜したい | 済み | —— |

## いま作る範囲（切り口）

S-01 〜 S-12。理由を 1 行。

## 噛み合っていないところ
```

最後の節は `../doc-shared/trace.md` の**両方向**の突き合わせを書く。
片方だけ数えない。**0 件なら 0 件と書く。**

## 適用範囲

- **出どころ**: Jeff Patton『User Story Mapping』。背骨・物語・切り口の 3 つが要点
- **対象**: 利用者が通しで使う道具。ライブラリには当てはまらない（通しの手順が無い）
- **当てはまらなくなる条件**:
  - 利用者が複数いて、通しの順番が違うとき（地図を分ける。1 枚に混ぜない）
  - 目標が書かれていないとき（2 で止まる）
  - 物語が 60 を超えるとき（畳み方を測っていない。`../doc-shared/judgement.md`）
- **確かめた環境**: Izuna のリポジトリ、2026-09-14

## 実行後に確かめる

**「作った」を成功にしない。** 次を全部満たすこと。

```bash
ls docs/plans/story-map/                   # 新しい版があり、前の版も残っている
git log --oneline -1 -- docs/plans/story-map/
```

- 番号が飛んでいない・重なっていない（前の版の番号がそのまま残っている）
- 物語のうち「状態」が空の行が 0 行
- 「噛み合っていないところ」に**両方向の数**が書いてある
- 背骨の活動が 10 以下

## 受け取る側が得るもの

- `docs/plans/story-map/YYYY-MM-DD.md`（版）と `README.md`（索引）
- ロードマップと突き合わせる番号（`S-nn`）
- 報告は**パスと、噛み合っていない件数（両方向）だけ**を 1 行で。中身を会話に繰り返さない

## 読む順序

本体はここまで。詳しいことは要るときだけ読む。

| 何を知りたいか | 読む |
| --- | --- |
| **ロードマップとの対応の付け方** | `../doc-shared/trace.md` |
| 入力の集め方、集まらないときの畳み方 | `../doc-shared/inputs.md` |
| 版の付け方、置き場、確かめ方 | `../doc-shared/versioning.md` |
| 書いてはいけないこと、成功の定義、長さ | `../doc-shared/writing.md` |
| 実例 | `docs/plans/story-map/`（Izuna の場合。2026-09-14 が最初の版） |
